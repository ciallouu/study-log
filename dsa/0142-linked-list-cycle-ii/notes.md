# 142. 环形链表 II

https://leetcode.cn/problems/linked-list-cycle-ii/

## 思路：141 找到相遇点 + 两指针同速找入口

找到相遇点后：

```java
ListNode p1 = head;    // 从【头】出发
ListNode p2 = slow;    // 从【相遇点】出发
while (p1 != p2) { p1 = p1.next; p2 = p2.next; }
return p1;             // 相遇处就是环入口
```

## 为什么这样对（推导）

设 head 到入口距离 `a`，入口到相遇点 `b`，环长 `L`：

- slow 走了 `a + b`
- fast 走了 `a + b + nL`（多转了 n 圈）
- 又因 fast = 2 × slow

```
a + b + nL = 2(a + b)
→ a + b = nL
→ a = nL - b = (n-1)L + (L - b)
```

**`L - b` 正是"从相遇点走到入口"的距离。**

所以：从头走 `a` 步、从相遇点走 `L-b` 步，会**同时到达入口**（`(n-1)L` 是整圈数，不影响位置）。

## 复杂度

- 时间 O(n)，空间 O(1)

## 踩的坑（真实犯过）

```java
// ❌ 错误：两个指针都从相遇点出发
ListNode p1 = fast;
ListNode p2 = slow;
while (p1 != p2) { ... }   // 一开始就相等，循环一次都不执行
return p1;                 // 直接返回了相遇点，不是入口！
```

**必须 `p1 = head`。**

危险之处：**不报错、样例可能侥幸通过**。实测 4 个环用例里对了 2 个、错了 2 个——因为当 `pos = 0`（入口就是 head）或恰好 `b = 0`（相遇点就是入口）时，错误答案和正确答案相同。

> 教训：链表题的"逻辑错但不报错"比编译错误危险得多，必须构造多个用例（不同 pos 值）才能暴露。

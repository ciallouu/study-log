# 27. 移除元素

https://leetcode.cn/problems/remove-element/

## 题目本质

不是"删除"，而是**把要保留的元素往前挤**。原地修改 + 返回新长度，判题器只取前 k 个元素比对。

## 思路一：快慢指针

- `slow` = 下一个该写入的位置（也就是已保留元素个数）
- 遍历 `fast`，遇到 `!= val` 就写到 `slow` 位置，然后 `slow++`

不变式：
- `[0, slow)`：已保留的元素
- `[slow, fast)`：已丢弃的占位
- `[fast, n)`：还没看

复杂度：时间 O(n)，空间 O(1)，每个保留元素最多赋值一次。

## 思路二：相向双指针

既然题目说"顺序可以改变"，就把末尾元素搬过来填坑，减少赋值次数。

**关键细节**：`left++` 只能写在 `else` 分支里。搬过来的新值还没检查过，必须原地再判断一次。

复杂度：时间 O(n)，空间 O(1)，只有 `val` 元素需要赋值。

## 两种解法对比

| 解法 | 时间复杂度 | 赋值次数 | 是否保序 |
|---|---|---|---|
| 快慢指针 | O(n) | 每个保留元素 1 次 | 保持原顺序 |
| 相向双指针 | O(n) | 仅 val 元素 | 打乱顺序（本题允许） |

## 踩的坑

1. `for (int i = 0; i <= nums.length; i++)` 会数组越界——下标上界是 `length - 1`
2. 一个变量不能既当计数器又当写指针，`k`（slow）的语义只能是"下一个该写入的位置"
3. `return k, nums;` 是 Python 元组语法，Java 只能返回一个 `int`
4. 判题器只取返回的 `k`，再截取 `nums` 前 k 个元素比较，k 之后的内容不参与判定（原地算法的约定）

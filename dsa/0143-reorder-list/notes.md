# 143. 重排链表

https://leetcode.cn/problems/reorder-list/

## 一句话

**876 找中点 + 206 反转 + 拉链式合并** —— 跟 234 回文链表是同一套积木的另一个拼法。

| 题 | 拼法 |
|---|---|
| 234 回文 | 找中点 + 反转 + **比对** |
| 143 重排 | 找中点 + 反转 + **合并** |

## 关键判断

### ① `fast = head.next` 这一行之差，决定了「奇偶还要不要 if」

| `fast` 起点 | `slow` 停在 | 前半段 / 后半段长度 | 需不需要分奇偶 |
|---|---|---|---|
| `head`（876 的写法） | 偶数→后半段第一个；奇数→正中 | 偶数 n/2 : n/2，奇数 (n+1)/2 : (n-1)/2 | **要**，切点位置不同 |
| **`head.next`（本题写法）** | **永远是前半段的最后一个** | 前半 `⌈n/2⌉`、后半 `⌊n/2⌋` | **不要**，切点永远只有一处 |

验证：

| 输入 | 循环后 `slow` | 前半段 | `second = slow.next` |
|---|---|---|---|
| `[1,2]` | 1 | `[1]` | `2` |
| `[1,2,3]` | 2 | `[1,2]` | `3` |
| `[1,2,3,4]` | 2 | `[1,2]` | `3` |

所以 `second = slow.next; slow.next = null;` 之后，**`second` 天然就是后半段头，不需要任何奇偶分支**。

### ② 先取再砍（顺序反了编译器不报错，只会给你错答案）

```java
ListNode second = slow.next;   // 先取
slow.next = null;              // 再砍
```

反过来的后果：
- `[1,2,3]`：先砍 `2.next=null` 再取 `cur = slow.next` → **`cur = null`** → 合并循环整个不跑 → 原样返回。
- `[1,2,3,4]`：`slow` 是后半段第一个节点，`slow.next = null` 砍掉的是它的后继 → 后半段只剩一个。

### ③ 合并时必须先存两边的 `next`

```java
ListNode temp1 = h.next;    // ❌ 若先写 h.next = pre，h.next 原值就丢了
ListNode temp2 = pre.next;
h.next = pre;
pre.next = temp1;
```

这是 206 反转同一个道理：**改指针之前必须把旧指向存住**。

### ④ 循环条件用短的一侧

`while (pre != null)`（后半段），而不是 `while (h != null)`。

因为后半段永远 ≤ 前半段，后半段走完时，前半段多出的节点**已经原地连好**，不需要再动。
**边界不需要判断，方向选对就自动正确。**

## 踩过的坑

| 坑 | 现象 | 原因 |
|---|---|---|
| `ListNode cur;` + 两个独立 `if` | 编译报 `变量 cur 可能尚未初始化` | javac 不认为两个 `if` 覆盖了所有情况，必须 `if/else` 或三目 |
| 保留旧的 `if(fast != null) cur = second.next;` | **奇数全对、偶数少一个节点**（静默丢数据） | `fast` 起点换成 `head.next` 后，`fast != null` 的含义从"奇数"翻转成"偶数"；`second` 已被砍断，跳过它就永久丢失 |
| 循环末尾多写 `temp1 = temp1.next; temp2 = temp2.next;` | 最后一轮 `temp2` 为 null → **NPE**（且完全多余） | 下一轮开头会重新 `temp1 = h.next`，这两个变量是"本轮快照" |

真实输出（偶数丢节点）：
```
[1,2]        你的 [1]          期望 [1,2]
[1,2,3,4]    你的 [1,4,2]      期望 [1,4,2,3]
[1,2,3,4,5,6]你的 [1,6,2,5,3]  期望 [1,6,2,5,3,4]
```

## 复杂度

- 时间 O(n)：找中点 n/2 + 反转 n/2 + 合并 n/2
- 空间 **O(1)**（原地改 `next`，注意签名是 `void`，不能 return 新链表）

## 三句话总结

1. `fast` 从 `head.next` 起步，`slow` 就永远停在前半段尾巴——**奇偶分支整个消失**。
2. **先取后砍**，顺序错了编译器不管。
3. 合并时**先存 next 再改指针**，循环条件**用短的一侧**。
